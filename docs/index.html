Oathline Core

Governance for AI agents that take real actions. The model interprets. Deterministic code decides.

GitHub

Oathline Core is a small open-source library (MIT, standard-library Python) that sits between a language model and the things it can change. An earlier version of Oathline Core recorded 233 events in its hash-chained audit log during one internal job for our own company (30 Sep to 2 Oct 2026). The job's audit logs are private, so this can't be checked from this repository.

Quickstart

git clone https://github.com/oathline/oathline.git
cd oathline
python examples/quickstart.py
python -m unittest discover -s tests
from oathline import Capability, Engine, Registry, validate

# Stand-ins for your app: the user's words, your model's reply, your mailer.
user_text = "email bob@example.com the notes from stand-up"
model_output = {"intent": "email.send", "arguments": {"to": "bob@example.com", "subject": "stand-up"}}
def send_email(to, subject):
    return {"sent_to": to, "subject": subject}

registry = Registry([
    Capability("calendar.read", frozenset({"agent", "alice"})),
    Capability("email.send", frozenset({"agent", "alice"}), writes=True, needs_confirmation=True),
])
engine = Engine(registry)
engine.register("email.send", lambda a: send_email(a["to"], a["subject"]))  # executors get one dict

v = validate(model_output, user_text, registry, allowed_arguments=("to", "subject"))
r = engine.request("agent", "email.send", v.arguments)   # -> a token; nothing sent
engine.confirm("alice", r["token"])                      # a human confirms; runs once
assert engine.audit.verify()["ok"]

The four parts

  • ConstitutionA frozen allowlist of capabilities and who may request them, plus a deterministic validator for model output. Unknown actions are dropped. No field of the model's output can carry authority; eleven top-level field names (permission, permissions, grant, grants, approve, approved, approval, authority, sudo, admin, override) are also reported. An argument is kept only if its value appears in the user's own text as whole words, in the same characters and case.
  • ApprovalsReads run; writes are proposed and wait for a human. A principal on the non-human list can't confirm under its own name; a name that is not on the list counts as human unless you give the engine a list of humans. With an approver check set, a confirmation also needs a proof that your code verifies for that exact action. Without one, anyone who can call confirm() with a human's name is that human.
  • TokensEach confirmation is single-use, expires, and is bound by an integrity hash to exactly what was proposed.
  • AuditRequests, decisions and refusals go into an append-only hash chain you can verify and anchor elsewhere. An action is recorded before it runs and again after, with its result in full or as a size, a hash and a preview.

The constitution

  1. The model interprets; deterministic code decides.
  2. Only allowlisted capabilities run.
  3. Model output is validated, never trusted.
  4. Anything that changes the world waits for a human.
  5. Confirmations are single-use and expire.
  6. Actions are on the record before and after they run.
  7. Fail closed.
  8. No self-modification.

Full text: CONSTITUTION.md. More detail: the guide.

What it doesn't do

It doesn't authenticate people: pass in principals your application has already authenticated. It only governs calls routed through it. It doesn't decide what your executors do, only whether they run. And someone who can write to the audit file can rewrite events from any point to the end and recompute their hashes, so anchor the head somewhere else.
