Oathline Quickstart Guide

Guide

Oathline Core has four parts. Each one is small enough to read in one sitting.

1. Constitution: capabilities and validation

Declare every action an agent may take as a Capability in a frozen Registry: who may request it, whether it writes, and who may approve it. Anything that isn't declared is refused. Once the registry is built there's no API to widen a grant at runtime.

validate() filters a model's proposed action before it reaches the engine. It keeps only known capabilities. It returns only capability names, arguments, a confidence and a list of violations, so no field of the model's output can carry authority; eleven top-level field names (permission, permissions, grant, grants, approve, approved, approval, authority, sudo, admin, override) are also reported. It keeps an argument only if it is declared and its value appears in the user's own text as whole words, in the same characters and case. Whatever the user wrote as a separate word passes (one word out of a longer phrase, or a piece of a number written with a space in it); a piece cut out of one word does not.

2. Approvals

Engine.request() runs reads straight away. A writing or gated capability returns a token instead of running. Engine.confirm() runs the stored arguments exactly once. It refuses a principal whose name is on the non-human list (model, agent and infrastructure identities). That is a check on a name: a name that is not on the list counts as human unless you pass humans=, and without an approver check, anyone who can call confirm() with a human's name is that human, including an agent that holds the token. Pass approver_check= to the engine and confirm() also needs a proof, which your function checks against the exact action being confirmed.

An agent can also propose() a gated action. It is confirmed under a human's name: a named approver, or a human granted the capability. It then runs once, as the agent's action on that human's authority.

from oathline import Capability, Engine, Registry

reg = Registry([Capability("site.deploy", frozenset({"builder-agent", "alice"}), writes=True,
                           needs_confirmation=True, approvers=frozenset({"alice"}))])
engine = Engine(reg, non_human=frozenset({"builder-agent"}))
engine.register("site.deploy", lambda a: {"deployed": a["version"]})
p = engine.propose("builder-agent", "site.deploy", {"version": "1.5.0"})   # nothing runs
engine.confirm("alice", p["token"])                                       # runs once, both principals recorded

3. Tokens

Confirmation tokens expire (30–3600 s), work once, and are bound by an integrity hash to the exact capability and arguments that were proposed. An expired or reused token is refused, and so is one whose stored arguments were changed while the stored hash was left alone. The hash has no key: someone who can write to the token store can change both.

4. Audit

AuditLog is an append-only SQLite hash chain. Triggers refuse UPDATE and DELETE; they stop accidents, not someone with the file, who can remove them. verify() detects a changed field, a deleted or swapped event and a broken hash. If you keep head() somewhere else and pass it to verify(expected_head=...), it also detects events cut off the end and a rewritten tail. An action is recorded before it runs and again after.

Limits

  • Oathline doesn't authenticate people. Pass in principals your application has already authenticated.
  • It decides whether an executor runs, not what the executor does.
  • Anyone who can rewrite the whole audit file can forge a consistent chain unless you anchor the head elsewhere.
